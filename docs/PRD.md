# MindMem 1.0 产品需求文档

> 版本：1.0 | 日期：2026-05-23 | 状态：Released

---

## 1. 产品概述

### 1.1 产品定位

MindMem 是一款具备持久化、多层记忆能力的 AI 智能伴侣。区别于无记忆的对话助手，MindMem 能够跨会话地记住用户的经历、身份信息、社会关系与重要事件，在每次对话中提供真正"认识你"的回应体验。

### 1.2 目标用户

- **主力用户**：有持续记录生活、工作、人际关系需求的知识工作者
- **典型场景**：日常情感陪伴、个人成长复盘、人际关系梳理、计划跟进

### 1.3 核心价值

| 维度 | 传统 AI 助手 | MindMem |
|------|------------|---------|
| 记忆持久性 | 单次会话 | 跨会话永久 |
| 用户理解深度 | 无 | 结构化多层画像 |
| 上下文关联 | 当次对话 | 历史事件 + 人际关系 |
| 回应个性化 | 通用回答 | 基于记忆的个性化 |

## 2. 功能模块

### 2.1 智能对话

**需求描述**  
用户通过自然语言与 AI 伴侣 MemoBot 对话，AI 的回应应融合记忆上下文，表现自然、克制、有分寸。

**核心需求**
- 流式输出对话内容（Streaming SSE）
- 系统提示自动注入四层记忆上下文（画像 → 事件 → 情节记忆）
- 支持多轮对话历史维护
- 每次对话结束后异步提取并更新记忆（Celery）

**AI 人设要求**
- 温柔知性的女性伙伴形象
- 情绪稳定，不使用感叹词、emoji 轰炸
- 禁止括号旁白（"（悄悄记下）"等）
- 不主动提"帮你记住了"
- 不替用户预设情绪

**验收标准**
- 回复延迟 < 3s（首字符）
- 记忆融入自然，不出现"我帮你记住了 XX"类硬植入
- 长期记忆（>7天）不主动在开场提起

---

### 2.2 历史对话

**需求描述**  
用户的每次对话会话自动保存，支持查看历史记录。

**核心需求**
- 会话自动持久化（SQLite）
- 对话标题自动生成（LLM 总结首条消息）
- 右侧抽屉展示历史会话列表
- 点击历史会话可恢复完整对话内容

**验收标准**
- 刷新页面后历史对话不丢失
- 历史列表按时间倒序排列，显示标题和时间

---

### 2.3 记忆画廊

记忆画廊是用户查看和管理所有记忆层的可视化界面，包含四个标签页。

#### 2.3.1 情节记忆（L1）

**需求描述**  
展示 Mem0 存储的碎片化情节记忆，支持时间轴浏览、标签过滤、搜索。

**核心需求**
- 按时间轴分组展示（今天 / 本周 / 更早）
- 支持标签过滤
- 支持关键词搜索
- 支持导入（JSON）/ 导出（JSON）
- 语义去重：相似度 > 0.92 跳过，0.78-0.92 更新，< 0.78 新增

**验收标准**
- 展示最近 500 条记忆（不截断）
- 导出文件包含所有记忆的完整内容

#### 2.3.2 用户画像（L2）

**需求描述**  
展示 LLM 从对话中提取的结构化用户信息，包含 8 个维度，每个字段带置信度。

**核心需求**

画像维度：

| 维度 | 字段示例 |
|------|---------|
| 基本信息 | 姓名、年龄、所在地 |
| 职业 | 职位、行业、技能、工作痛点 |
| 兴趣偏好 | 长期兴趣、近期关注、内容偏好 |
| 价值观 | 技术态度、敏感话题 |
| 习惯 | 活跃时段、提问深度 |
| 目标与痛点 | 短期/长期目标、当前痛点 |
| 社会关系 | 家庭结构、重要关系 |
| 交互偏好 | 常聊话题、明确偏好 |

- 字段按置信度阈值（≥0.5）过滤显示
- 自动处理记录：可折叠面板，展示 AI 如何解决字段冲突（追加/替换/合并）
- 字段冲突自动决策，无需用户手动确认

**冲突处理规则**

| 字段类型 | 处理策略 |
|---------|---------|
| 累加字段（技能、目标、痛点） | 追加新项，去重 |
| 覆盖字段（职位、年龄、所在地） | 高置信度值替换低置信度值 |
| 合并字段（社会关系） | 深度对象合并 |

**验收标准**
- 置信度 < 0.5 的字段不显示
- 自动处理记录展示：动作类型（追加/替换/合并）+ 字段 + 旧值/新值 + 时间
- 画像随对话自动更新，无需手动触发

#### 2.3.3 事件记忆（L3）

**需求描述**  
展示从对话中提取的结构化事件，含 6 种类型，支持过滤与管理。

**事件类型**

| 类型 | 说明 | 重要度 |
|------|------|-------|
| 计划 (plan) | 用户的近期/未来安排 | 0.9 |
| 成就 (achievement) | 完成的目标/里程碑 | 0.8 |
| 痛点 (pain_point) | 反馈的困扰/问题 | 0.8 |
| 经历 (experience) | 一般性生活事件 | 0.5 |
| 反馈 (feedback) | 对产品/服务/他人的评价 | 0.5 |
| 状态变化 (status_change) | 工作/生活状态转变 | 0.7 |

**核心需求**
- 事件列表展示（类型、摘要、发生时间、重要度、提及次数）
- 按类型和状态过滤
- 支持删除（硬删除）和归档（软删除）
- 事件注入系统提示：重要度 ≥0.5 或类型为 plan，最多 15 条
- 语义去重：SQLite 关键词预过滤 + Qdrant 向量相似度 0.75 阈值
- 重复事件追加提及次数而非重复创建

**验收标准**
- 事件从对话中自动提取（Celery 异步）
- 相似事件不重复创建，mention_count +1

#### 2.3.4 社会关系图（L4）

**需求描述**  
以树状结构可视化展示用户提及的人际关系。

**核心需求**
- 以用户为根节点的树状关系图（SVG 渲染）
- 节点展示：姓名、关系类型、描述
- 按关系大类分组（家人/朋友/同事等）
- 支持节点展开/折叠
- 空数据时展示引导提示

**验收标准**
- 多个同类关系正确展示为独立节点
- 与用户画像中的 social.relationships 数据保持同步

---

### 2.4 Prompt 透明度

**需求描述**  
用户可查看每次对话时实际激活了哪些记忆（Prompt 内容）。

**核心需求**
- 每次 AI 回复下方提供"查看 Prompt"入口
- 展示：记忆内容、用户画像片段、近期事件片段
- 以 SSE 事件 `type:prompt` 传输

**验收标准**
- Prompt 抽屉内容与实际注入系统提示一致

## 3. 非功能需求

### 3.1 性能

- 对话首字符延迟 < 3s（正常网络）
- 记忆提取为异步操作，不阻塞对话
- 记忆画廊加载 < 2s

### 3.2 可靠性

- Celery 任务失败不影响主对话流程
- 数据库迁移向后兼容（新增字段通过 try-except 容错）
- 记忆去重失败时降级为直接保存

### 3.3 安全性

- JWT 鉴权，所有 API 需登录
- 用户数据严格隔离（按 user_id）
- 支持 DEV_MODE 便于本地开发

### 3.4 部署

- Docker Compose 一键启动（5 个服务）
- 支持 `.env` 文件配置 API Key 和密钥
- 前端热更新开发模式

---

## 4. 用户旅程

```
用户登录
  → 进入聊天界面
  → 与 MemoBot 对话（自然语言）
  → AI 基于四层记忆回应
  → 对话结束后后台异步提取记忆
    ├── L1 情节记忆 → Mem0 + Qdrant
    ├── L2 用户画像 → SQLite（自动冲突处理）
    └── L3 事件记忆 → SQLite + Qdrant（去重）
  → 用户可在记忆画廊查看/管理所有记忆
  → 下次对话时记忆自动融入
```

---

## 5. 已知限制（1.0）

- 不支持多用户社交/分享
- 不支持语音输入
- 记忆衰减为定时批量处理（非实时）
- 关系图只支持二层展示（用户 → 关系人）
- 暂无记忆主动遗忘（forget）命令
