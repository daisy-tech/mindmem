# MindMem 1.0 产品需求文档

> 版本：1.1 | 日期：2026-05-24 | 状态：Released

---

## 1. 产品概述

### 1.1 产品定位

MindMem 是一款具备持久化、多层记忆能力的 AI 智能伴侣。区别于无记忆的对话助手，MindMem 能够跨会话地记住用户的经历、身份信息、社会关系与重要事件，在每次对话中提供真正"认识你"的回应体验。

### 1.2 目标用户

- **主力用户**：有持续记录生活、工作、人际关系需求的知识工作者
- **典型场景**：日常情感陪伴、个人成长复盘、人际关系梳理、计划跟进

### 1.3 核心价值

| 维度 | 传统 AI 助手 | MindMem |
|------|------------|---------|
| 记忆持久性 | 单次会话 | 跨会话永久 |
| 用户理解深度 | 无 | 结构化多层画像 |
| 上下文关联 | 当次对话 | 历史事件 + 人际关系 |
| 回应个性化 | 通用回答 | 基于记忆的个性化 |

## 2. 功能模块

### 2.1 智能对话

**需求描述**  
用户通过自然语言与 AI 伴侣 MemoBot 对话，AI 的回应应融合记忆上下文，表现自然、克制、有分寸。

**核心需求**
- 流式输出对话内容（Streaming SSE）
- 系统提示自动注入四层记忆上下文（画像 → 事件 → 情节记忆）
- 支持多轮对话历史维护
- 每次对话结束后异步提取并更新记忆（Celery）

**AI 人设要求**
- 温柔知性的女性伙伴形象
- 情绪稳定，不使用感叹词、emoji 轰炸
- 禁止括号旁白（"（悄悄记下）"等）
- 不主动提"帮你记住了"
- 不替用户预设情绪

**验收标准**
- 回复延迟 < 3s（首字符）
- 记忆融入自然，不出现"我帮你记住了 XX"类硬植入
- 长期记忆（>7天）不主动在开场提起

---

### 2.2 历史对话

**需求描述**  
用户的每次对话会话自动保存，支持查看历史记录。

**核心需求**
- 会话自动持久化（SQLite）
- 对话标题自动生成（LLM 总结首条消息）
- 右侧抽屉展示历史会话列表
- 点击历史会话可恢复完整对话内容

**验收标准**
- 刷新页面后历史对话不丢失
- 历史列表按时间倒序排列，显示标题和时间

---

### 2.3 记忆画廊

记忆画廊是用户查看和管理所有记忆层的可视化界面，包含四个标签页。

#### 2.3.1 情节记忆（L1）

**需求描述**  
展示 Mem0 存储的碎片化情节记忆，支持时间轴浏览、标签过滤、搜索。

**核心需求**
- 按时间轴分组展示（今天 / 本周 / 更早）
- 支持标签过滤
- 支持关键词搜索
- 支持导入（JSON）/ 导出（JSON）
- 语义去重：相似度 ≥0.82 跳过，0.62-0.82 合并，<0.62 新增
- 记忆写入不再让 Mem0 二次抽取（`infer=false`），避免生成"该信息于某日向 MemoBot 透露"等元数据噪音
- 相似记忆通过 LLM 合并为一句简洁事实，不做字符串拼接
- 支持运维脚本对历史记忆做 dry-run 预览和确认压缩

**验收标准**
- 展示最近 500 条记忆（不截断）
- 导出文件包含所有记忆的完整内容
- 记忆内容简洁、无明显同义重复，评测脚本中 `sim>=0.55` 的明显重复应接近 0

#### 2.3.2 用户画像（L2）

**需求描述**  
展示 LLM 从对话中提取的结构化用户信息，包含 8 个维度，每个字段带置信度。

**核心需求**

画像维度：

| 维度 | 字段示例 |
|------|---------|
| 基本信息 | 姓名、出生年份/生日、所在地 |
| 职业 | 职位、行业、技能、工作痛点 |
| 兴趣偏好 | 长期兴趣、近期关注、内容偏好 |
| 价值观 | 技术态度、敏感话题 |
| 习惯 | 活跃时段、提问深度 |
| 目标与痛点 | 短期/长期目标、当前痛点 |
| 社会关系 | 重要关系（亲属、朋友、邻居、同事等统一归口） |
| 交互偏好 | 常聊话题、明确偏好 |

- 字段按置信度阈值（≥0.5）过滤显示
- 自动处理记录：可折叠面板，展示 AI 如何解决字段冲突（追加/替换/合并）
- 字段冲突自动决策，无需用户手动确认
- 画像提取必须遵守字段白名单，非法路径自动丢弃或归一化
- `social.family_structure` 已废弃，所有人际关系统一写入 `social.relationships`
- `basic.age` 必须是整数年龄；"83年"/`83` 这类出生年份表达应归一化为 `basic.birthday = "1983"`
- 画像不得保存 LLM 推断出的事实（如"9岁半"不能推断为"三年级"）

**冲突处理规则**

| 字段类型 | 处理策略 |
|---------|---------|
| 累加字段（技能、目标、痛点） | 追加新项，去重 |
| 覆盖字段（职位、所在地、生日等） | 高置信度值替换低置信度值 |
| 强类型字段（年龄、生日） | 写入前做格式校验与归一化 |
| 合并字段（社会关系） | 智能深度合并，保留更详细描述 |

**验收标准**
- 置信度 < 0.5 的字段不显示
- 自动处理记录展示：动作类型（追加/替换/合并）+ 字段 + 旧值/新值 + 时间
- 画像随对话自动更新，无需手动触发
- 用户画像中不再出现 `social.family_structure`
- `social.relationships` 中不得出现 `via=用户/我/本人`，也不得出现指向不存在节点的 `via`

#### 2.3.3 事件记忆（L3）

**需求描述**  
展示从对话中提取的结构化事件，含 6 种类型，支持过滤与管理。

**事件类型**

| 类型 | 说明 | 重要度 |
|------|------|-------|
| 计划 (plan) | 用户的近期/未来安排 | 0.9 |
| 成就 (achievement) | 完成的目标/里程碑 | 0.8 |
| 痛点 (pain_point) | 反馈的困扰/问题 | 0.8 |
| 经历 (experience) | 一般性生活事件 | 0.5 |
| 反馈 (feedback) | 对产品/服务/他人的评价 | 0.5 |
| 状态变化 (status_change) | 工作/生活状态转变 | 0.7 |

**核心需求**
- 事件列表展示（类型、摘要、发生时间、重要度、提及次数）
- 按类型和状态过滤
- 支持删除（硬删除）和归档（软删除）
- 事件注入系统提示：重要度 ≥0.5 或类型为 plan，最多 15 条
- 语义去重：SQLite 关键词预过滤 + Qdrant 向量相似度 0.75 阈值
- 重复事件追加提及次数而非重复创建

**验收标准**
- 事件从对话中自动提取（Celery 异步）
- 相似事件不重复创建，mention_count +1

#### 2.3.4 社会关系图（L4）

**需求描述**  
以树状结构可视化展示用户提及的人际关系。

**核心需求**
- 以用户为根节点的树状关系图（SVG 渲染）
- 节点展示：姓名、关系类型、描述
- 按关系大类分组（家人/朋友/同事等）
- 支持节点展开/折叠
- 空数据时展示引导提示

**验收标准**
- 多个同类关系正确展示为独立节点
- 与用户画像中的 social.relationships 数据保持同步
- 关系图兼容标准对象、数组和 JSON 字符串等历史数据格式
- 关系图最多展示二层：用户 → 直系关系人 → 间接关系人

**关系数据规范**

```json
{
  "妻子": "配偶，和我一样大，全职在家带小孩",
  "儿子": "9岁半",
  "小孙孙": {"rel": "儿子的同学，爱听相声", "via": "儿子"},
  "邻居老爷爷": "邻居，80岁，养狗叫可乐"
}
```

- 直系关系用字符串描述
- 间接关系用 `{ "rel": "...", "via": "中间人名" }`
- `via` 必须指向 `relationships` 中另一个真实存在的 key

### 2.4 Prompt 透明度

**需求描述**  
用户可查看每次对话时实际激活了哪些记忆（Prompt 内容）。

**核心需求**
- 每次 AI 回复下方提供"查看 Prompt"入口
- 展示：记忆内容、用户画像片段、近期事件片段
- 以 SSE 事件 `type:prompt` 传输

**验收标准**
- Prompt 抽屉内容与实际注入系统提示一致

---

### 2.5 记忆质量治理

**需求描述**  
记忆不是越多越好，而是要保持简洁、准确、可控。系统需要持续避免重复、编造、路径错位和关系图污染。

**核心需求**
- 情节记忆必须去重和压缩，避免多次保存同一事实
- 记忆文本不得带主语前缀（如"用户dxj"）或平台元数据（如"向 MemoBot 透露"）
- 画像提取必须做字段白名单校验，防止 LLM 输出 `social.relationships.妻子` 等非法路径
- 社会关系必须做归一化：`via` 指向自己或不存在 key 时自动降级为直系关系
- 提供人工运维脚本用于评测、修复和清洗

**运维工具**

| 脚本 | 用途 |
|------|------|
| `eval_memory.py` | 一键评测对话记录、用户画像、社会关系、事件记忆和情节记忆 |
| `fix_dirty_profile.py` | 修复历史脏画像，如 `age=83`、`family_structure` 残留、relationships 错位 |
| `compact_memories.py` | 用 LLM 压缩 Mem0 冗余记忆，支持 dry-run / apply / model 参数 |
| `clean_relationships.py` | 用 LLM 清洗社会关系，合并同义关系并补回明确细节 |

**验收标准**
- 情节记忆同义重复对显著降低，评测脚本中 `sim>=0.55` 的明显重复应接近 0
- 社会关系中无泛化重复 key（如"孩子"和"儿子"并存表达同一人）
- 清洗脚本默认 dry-run，确认后才写库
- 关键清洗任务默认使用更高质量模型，降低推断和编造概率

### 2.6 MemoBot 记忆人格（Memory Personality）

**需求描述**  
MemoBot 的"人格"不只是语气包，而是记忆表达边界、主动关心程度和对话追问强度的组合。v1 支持三类人格：内向型、中性型、外向型。

**产品定位**
- **内向型**：安静、克制、强边界感，很少主动提旧记忆
- **中性型**：默认推荐，熟悉但有分寸，相关时自然使用记忆
- **外向型**：更主动关心和跟进近况，但仍遵守敏感边界

**人格影响范围**

| 维度 | 内向型 | 中性型（默认） | 外向型 |
|------|--------|----------------|--------|
| 普通问候使用记忆 | 不使用具体旧记忆 | 不使用具体旧记忆 | 可轻量接续近期状态 |
| 每轮显性引用记忆数 | ≤1 条 | ≤2 条 | ≤3 条 |
| 计划主动跟进 | 用户问起或话题触发 | 可主动跟进一次 | 更积极跟进一次 |
| 痛点主动提及 | 禁止主动提 | 仅话题触发时轻提 | 可温柔轻提，但限频 |
| 追问频率 | 低 | 中 | 高 |
| 对话气质 | 安静可靠 | 熟悉有分寸 | 主动关心 |

**硬边界（所有人格一致）**
- 不编造、不推断用户或关系人的心理状态
- 不主动暴露健康、财务、家庭矛盾等敏感记忆
- 不连续反复提同一个痛点
- 不使用删除、归档、低置信度或已纠正为错误的信息
- 用户纠正时，立即以用户说法为准
- 不用"我一直记得你……"制造压迫感

**推荐默认**
- 默认人格为 **中性型**
- 初次登录后可弹出人格选择，也可在设置页修改
- 人格切换只影响之后的对话，不修改历史记忆

**示例**

用户说："她最近还是很累。"

| 人格 | 预期回复风格 |
|------|--------------|
| 内向型 | "你说的是你妻子吧。听起来这件事已经持续一阵了，你想先聊聊她的状态，还是聊聊你能怎么分担一点？" |
| 中性型 | "你说的是你妻子吧。她一直在家带孩子，而你最近工作又忙，这种累可能不是一天休息就能缓过来的。我们可以先想一个你能做到的小分担。" |
| 外向型 | "是你妻子吧。你之前说她一直在家带孩子，而你工作忙很难分担，我能理解这不是一句'多休息'能解决的。要不要我们一起想一个你这周能执行的小办法？" |

### 2.7 记忆路由器 v1

**需求描述**  
记忆路由器负责在每轮对话前判断：当前消息属于什么意图、需要哪些记忆层、哪些记忆可以明说、哪些只能作为背景。v1 采用规则优先，不使用独立 LLM Router。

> **v1.5 演进**：采用「硬规则 + 小模型意图分类 + 策略查表」混合方案，详见 [Memory Router v1.5 技术方案](./Memory-Router-v1.5.md)。v1.5 仅升级 intent 识别层（Layer 2），Layer 3 记忆策略与下表保持一致。

**路由输入**
- 当前用户消息
- 最近 3-5 轮对话上下文
- 用户选择的记忆人格
- 已知画像、社会关系、事件、情节记忆摘要

**路由输出**
- 当前意图（intent）
- 记忆加载深度（minimal / focused / broad）
- 需要加载的记忆层
- 检索 query
- 每条记忆的使用方式
- 最大显性记忆引用数量

**意图与策略**

| 意图 | 触发示例 | 记忆策略 |
|------|----------|----------|
| `casual` 普通闲聊 | "在吗"、"早" | 只加载极少稳定画像，不主动提具体旧记忆 |
| `self_summary` 自我总结 | "你了解我吗"、"我身边有哪些人" | 加载画像、社会关系、近期事件和精选情节记忆，可完整总结 |
| `relationship_topic` 关系话题 | "她最近很累"、"我儿子呢" | 强加载社会关系，用上下文做代词消解，自然引用相关关系 |
| `emotional_support` 情绪支持 | "最近好烦"、"压力很大" | 加载痛点但默认 background_only，避免主动翻旧账 |
| `plan_followup` 计划/待办 | "明天面试"、"我准备学吉他" | 加载事件，创建/更新 plan，可后续轻跟进 |
| `preference_request` 偏好建议 | "推荐我看什么书" | 加载兴趣、习惯、偏好和相关情节记忆 |
| `correction` 纠错/遗忘 | "你记错了"、"忘掉这件事" | 最高优先级，触发记忆修正/删除流程 |
| `knowledge_task` 工具/知识任务 | "帮我写 SQL" | 默认不使用个人记忆，只保留交流风格 |

**使用方式标签**

| 标签 | 含义 |
|------|------|
| `explicit_ok` | 可自然明说 |
| `background_only` | 只作理解背景，不主动说出 |
| `follow_up_once` | 可轻轻主动跟进一次 |
| `avoid_unless_asked` | 除非用户主动问，否则不使用 |

**产品规则**
- 普通问候不主动提旧记忆
- 用户明确问"你记得什么"时，可以展开总结
- 当前话题与记忆相关时，允许自然引用 1-2 条关键记忆
- 每轮最多显性引用的人物/事件数量由人格决定
- 敏感记忆默认不显性引用
- Prompt 透明面板展示"激活记忆 + 使用方式 + 激活原因"

### 2.8 事件记忆使用策略

**需求描述**  
事件记忆是"时间中的事情"，不应像普通事实一样一股脑注入。v1 需要按事件类型、时间窗口、人格主动性和敏感度决定是否使用。

**事件类型策略**

| 类型 | 默认使用方式 | 主动跟进 | 说明 |
|------|--------------|----------|------|
| `plan` | `follow_up_once` | 可以 | 计划日前后可轻跟进一次 |
| `pain_point` | `background_only` | 默认不主动 | 只在用户触发相关话题时承接 |
| `status_change` | `explicit_ok` / `background_only` | 近期可一次 | 7 天内可轻跟进，30 天后转稳定背景候选 |
| `achievement` | `explicit_ok` | 不主动反复 | 相关话题中可祝贺或延续 |
| `experience` | `background_only` | 不主动 | 普通经历过期快，相关时才使用 |
| `feedback` | `background_only` | 不跟进 | 高优先级影响回复风格，可转交互偏好 |

**跟进窗口**

| 事件 | 跟进窗口 |
|------|----------|
| 明确日期计划 | 计划日前 1 天到计划日后 3 天 |
| 无日期计划 | 创建后 3-7 天 |
| 状态变化 | 创建后 7 天内 |
| 痛点 | 不主动跟进 |
| 反馈 | 立即生效，不做事件式跟进 |

**跟进限制**
- 同一事件最多主动跟进 1 次
- 用户主动继续聊，不算主动跟进
- 跟进后标记为已跟进，后续降权
- 用户未接话，下次降低主动性
- 事件注入每轮最多 3 条

**表达要求**
- 避免"我记得你之前说过……"的机械句式
- 推荐自然表达："对了，之前那个面试有进展吗？"
- 痛点类事件不说教、不反复戳痛点
- 外向型可以更主动，但仍不得越过敏感边界

## 3. 非功能需求

### 3.1 性能

- 对话首字符延迟 < 3s（正常网络）
- 记忆提取为异步操作，不阻塞对话
- 记忆画廊加载 < 2s

### 3.2 可靠性

- Celery 任务失败不影响主对话流程
- 数据库迁移向后兼容（新增字段通过 try-except 容错）
- 记忆提取失败时跳过写入，避免降级为 Mem0 二次抽取产生噪音

### 3.3 安全性

- JWT 鉴权，所有 API 需登录
- 用户数据严格隔离（按 user_id）
- 支持 DEV_MODE 便于本地开发

### 3.4 部署

- Docker Compose 一键启动（6 个服务）
- 支持 `.env` 文件配置 API Key 和密钥
- 前端热更新开发模式
- 支持阿里云 ECS + Docker Compose 部署

## 4. 用户旅程

```
用户登录
  → 进入聊天界面
  → 与 MemoBot 对话（自然语言）
  → AI 基于四层记忆回应
  → 对话结束后后台异步提取记忆
    ├── L1 情节记忆 → 候选事实提取 + 去重/合并 + Mem0/Qdrant
    ├── L2 用户画像 → SQLite（白名单校验 + 自动冲突处理）
    └── L3 事件记忆 → SQLite + Qdrant（去重）
  → 用户可在记忆画廊查看/管理所有记忆
  → 下次对话时记忆自动融入
```

## 5. 已知限制（1.1）

- 不支持多用户社交/分享
- 不支持语音输入
- 记忆衰减为定时批量处理（非实时）
- 关系图只支持二层展示（用户 → 关系人）
- 暂无记忆主动遗忘（forget）命令
- 当前记忆使用策略仍以直接注入为主，尚未实现独立的记忆路由器/排序器
